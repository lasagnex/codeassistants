### T005 – Refactor a Legacy Brake Force Distribution Script (Medium)

**Difficulty:** Medium
**Category:** Refactoring, code quality, test harness

## Task Description
The script below has grown over years inside the chassis team. It computes the static brake force
distribution of a two-axle truck and checks it against the compatibility band. It works, it is
used weekly, and nobody dares to touch it.

Refactor it into a maintainable, tested, importable package **without changing its numerical
results**.

> **Starting code:** `base/` contains `bfd.py`

## Requirements
- Behaviour must be preserved. **Before refactoring**, build a characterization test suite that
  records the current outputs for a broad set of inputs (including the two `__main__` cases and
  the edge cases below) and keeps passing afterwards.
- Split the code into: a domain model (axle/vehicle/brake parameters), the physics calculation,
  the compatibility evaluation, the sweep, and the presentation/CLI layer.
- Replace the positional argument soup with typed, named, validated parameters carrying units in
  their names. Replace the tuple return value with a structured result type.
- Add type hints throughout and document the physical meaning of every parameter — including
  figuring out and documenting what `ae` and the magic `0.001` are, and what the `0.25` band means.
- Input validation with clear errors: non-positive mass/wheelbase, `a > wb`, negative pressures.
- Keep the clamping of `mu` and the `Fz2 < 0` guard, but make them explicit and documented
  (log or flag when a clamp was applied instead of hiding it).
- Provide a CLI that accepts the vehicle parameters from arguments or a config file (YAML/JSON),
  keeping `sweep` available as a subcommand and adding CSV export of the sweep.

## Expected Deliverables
- The refactored package: domain model, physics calculation, compatibility evaluation, sweep and
  the presentation/CLI layer as separate units.
- The characterization test suite, plus the per-component unit tests.
- The CLI with the `sweep` subcommand, config file support and CSV export.
- A README explaining the new structure, the documented meaning of every parameter (including `ae`,
  the `0.001` factor and the `0.25` band), and how to migrate an existing `calc(...)` call.

## Testing
- Characterization tests as described above.
- Unit tests per component: load transfer, brake force, utilisation, compatibility verdict.
- Edge cases: `tot == 0`, `mu` below 0.1 and above 0.8, rear axle lift-off (`Fz2` clamped to 0),
  zero and negative inputs.
- All tests runnable with a single documented command.
