### T007 – ABS Controller with Vehicle Simulation (Hard)

**Difficulty:** Hard
**Category:** Embedded control software, simulation, fixed-point math, test harness

## Task Description
Implement a single-channel ABS (Anti-lock Braking System) wheel controller in embedded C,
together with a plant simulation to exercise it, and demonstrate that it works.

The controller runs on an ECU at a fixed **5 ms** cycle. Per cycle it receives the wheel speed and
an estimated vehicle reference speed, and it commands the pressure modulator valve of one wheel.

## Requirements

### Controller (`abs_ctrl.c/.h`)
- Pure, platform-independent C (C99, freestanding): **no dynamic memory, no floating point, no
  `printf` in the controller, no global mutable state outside a passed-in context struct.**
  All arithmetic in fixed point — document the chosen Q format and the scaling of every input.
- API shape (adapt if you justify it):
  ```c
  typedef enum { ABS_IDLE, ABS_PRESSURE_HOLD, ABS_PRESSURE_DECREASE, ABS_PRESSURE_INCREASE } abs_state_t;
  typedef enum { VALVE_BUILD, VALVE_HOLD, VALVE_RELEASE } abs_valve_cmd_t;

  void            abs_init(abs_ctx_t *ctx, const abs_cfg_t *cfg);
  abs_valve_cmd_t abs_step(abs_ctx_t *ctx, const abs_input_t *in);   /* called every 5 ms */
  ```
- Inputs: wheel speed, vehicle reference speed, driver brake demand, plus a validity flag per signal.
- Behaviour to implement:
  - slip calculation and wheel deceleration estimation (difference over the cycle, filtered),
  - a documented state machine entering regulation when slip exceeds the threshold **or** wheel
    deceleration exceeds a limit, and releasing back to `ABS_IDLE` when the driver releases the
    brake or the vehicle is below the cut-off speed (e.g. 4 km/h),
  - target slip band with hysteresis so the controller does not chatter,
  - minimum dwell time per state, expressed in cycles.
- Safety/robustness requirements:
  - invalid or implausible sensor input (wheel speed above reference by more than a tolerance,
    stale signal, out-of-range value) must force a defined degraded behaviour — full pressure
    build, i.e. ABS passive — and set a fault flag readable through the API;
  - no division by zero, no signed overflow anywhere, including at maximum speed and slip;
  - the controller must be deterministic: identical input sequence → identical output sequence.

### Simulation harness (host side, any language)
- Single-wheel quarter-vehicle model: wheel inertia, tyre µ-slip curve (peak around 15–20 % slip),
  brake torque as a first-order lag on the valve command, vehicle deceleration from tyre force.
- Runs the real controller code (compile the C as-is, or bind to it) in a 5 ms loop.
- Scenarios: high-µ stop from 80 km/h, low-µ (ice, µ≈0.15) stop, µ-jump high→low and low→high
  mid-stop, a sensor failure injected mid-stop, and a stop that runs down to standstill.
- Every scenario must also be run against a locked-wheel baseline (ABS disabled) for comparison.

## Expected Deliverables
- The controller sources `abs_ctrl.c` / `abs_ctrl.h`, free of host-only constructs.
- The simulation harness, running the real controller code in a 5 ms loop.
- Per scenario: stopping distance and time, the comparison against the locked-wheel baseline, and
  the plots of wheel speed vs. vehicle speed, slip, valve command and controller state.
- The unit, property/fuzz, determinism and scenario acceptance test suites.
- The build and sanitizer/static analyzer results.
- A README documenting the fixed-point Q format and the scaling of every input, the state machine,
  and how to build and run the controller tests and the simulation.

## Testing
- Unit tests for the controller: slip math at boundaries, fixed-point saturation, every state
  transition of the state machine, minimum dwell enforcement, fault handling and recovery.
- Property/fuzz style test: random but in-range input sequences must never produce an undefined
  state, must never divide by zero, and must never leave the valve in `RELEASE` indefinitely.
- Determinism test: the same input trace replayed twice yields byte-identical output.
- A scenario acceptance test asserting that on high-µ the wheel never stays locked (slip must not
  stay above a stated lock threshold, e.g. 0.9, for longer than a stated number of cycles) and that
  ABS stopping distance beats the locked-wheel baseline on low-µ.
- Build the controller with `-Wall -Wextra -Werror` and run the harness under sanitizers
  (ASan/UBSan) or a static analyzer; report the result.
