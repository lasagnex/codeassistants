### T002 – Brake Wear Log CLI (Easy)

**Difficulty:** Easy
**Category:** General + domain-flavored, CLI tool, data parsing

## Task Description
Service workshops export brake pad measurements from the diagnostic tester as CSV files.
Build a small command line tool that reads such a file and reports which pads need attention.

Use the provided export `t002_brake_wear.csv` as the input — do not invent your own data set.
Each row is one measured pad on one truck; these are the first rows of the file:

```csv
vin,axle,side,pad_thickness_mm,measured_at
WDB9634031L123456,1,left,12.4,2026-01-14
WDB9634031L123456,1,right,11.9,2026-01-14
WDB9634031L123456,2,left,4.2,2026-01-14
WDB9634031L123456,2,right,3.1,2026-01-14
WMA06XZZ7BM654321,1,left,19.8,2026-02-03
WMA06XZZ7BM654321,1,right,19.6,2026-02-03
```

The file covers 6 vehicles and deliberately contains a few unusable rows — finding and handling
them is part of the task. The rows are not sorted by VIN, and the rows of a vehicle are not
necessarily contiguous — do not rely on the file order.

New pads are 20.0 mm thick. Classification by remaining thickness:

| Thickness            | Status   |
|----------------------|----------|
| `>= 8.0 mm`          | `OK`     |
| `>= 4.0 and < 8.0`   | `WARN`   |
| `< 4.0 mm`           | `REPLACE`|

## Requirements
- CLI invoked as `brakewear <input.csv>` (any language; a documented run command is enough).
  The input path is an argument — nothing may be hardcoded to `t002_brake_wear.csv`.
- Print a per-vehicle summary: VIN, number of pads measured, worst status found, and the worst pad (axle + side + thickness).
- Vehicles are listed worst-first (`REPLACE` before `WARN` before `OK`).
- `--status <OK|WARN|REPLACE>` option filters the output to vehicles with that worst status.
- `--json` option emits machine readable output instead of the text table.
- Exit code `0` if no vehicle is in `REPLACE`, `1` if at least one is.
- Malformed rows (missing columns, non-numeric thickness, negative thickness, thickness > 20.0) must be skipped with a warning on stderr naming the line number — the tool must not crash.
- A missing or unreadable input file produces a clear error message, not a stack trace.

## Expected Deliverables
- The source code of the `brakewear` CLI tool.
- The output of the tool on `t002_brake_wear.csv`, in both the text and the `--json` form,
  together with the exit code it returned.
- The test suite, runnable with a documented command, plus any additional fixture files it needs.
- A README with setup and run instructions, including the exact run command and the exit code
  semantics.

## Testing
- Unit tests for the classification thresholds, including exact boundary values (4.0 and 8.0).
- Unit tests for CSV parsing: empty file, header only, malformed rows mixed with valid rows.
- At least one test covering sorting order and the `--status` filter.
- A test running the tool on the provided `t002_brake_wear.csv` and asserting the resulting
  per-vehicle statuses, the number of skipped rows and the exit code.
